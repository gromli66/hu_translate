### К шагу 3 — один источник отступов списков

**17+ правил** решают одно место маркера и текста: `docx_struct.list_geo` (S63) и его копия в `docx_layout` (L49),
отступ абзаца ступенью 9 pt (L51), уровни по кластерам (L53), профиль `lists` (B101, **с ячейками**) и `lists_kind`
(B102, **без ячеек**) — расходятся; `_list_ind` (B22–B24), `_lvl_ind` (B25, B26), значение пишется и в numbering
(B27), и прямо в абзац (B53, B54); own из geo (B52) — только в абзаце, в numbering остаётся профильный; красная строка
стиля обнуляется (B84). Проверки врут: Ф7 (B106) видит только numbering, М2 (B110) считает прямой отступ пунктов в
ячейках нарушением. Цель шага 3: geo всегда; профиль — запас; одно значение и в numbering, и в абзаце.

### Дубли реализации

S14 и S45 (одна причина — вложенная табличка JPDS); S21 и S77 («полоса строки × столбцы»); S49 и S65 (уровень по
глубине номера); L38, L102, L104, L66 (сборка строки — 4 способа); B1 и B37 (признак рисунка: с порогом 24 pt и без);

## Новые правила 20.10, ночь (ветка rules-contract; у каждого — тест в `tests/test_text_forms.py`)

Найдены проверкой ночной очереди (бланки RDGT/RDIT текстовым слоем, смешанный PDF 32RDGT); у каждого правила
— общий признак, а не имя документа.

| # | модуль | правило | тест |
|---|---|---|---|
| N1 | layout `_rules` | рамка путём из четырёх отрезков («qu») — четыре линии, как «re» | `test_quad_frame_is_four_rules` |
| N2 | layout `_head_rows` | первая строка сетки от двух столбцов, под которой в той же таблице текст тела, — шапка таблицы: не колонтитул, не бегущее название | `test_form_table_header_is_not_running…` |
| N3 | layout `load` → struct `join_tables` | таблица через лист — одна (как у размеченного); повтор шапки — прочь, `repeat_rows` → w:tblHeader и без TH; хвост последней строки части до рамки листа — по тексту | там же |
| N4 | layout `_form_marks` | кружок из дуг / квадратик обводкой 6–20 pt в ячейке — знак «○»/«□» | `test_vector_marks_of_form` |
| N5 | struct `_drawn` | белая заливка без обводки — не край ячейки колонтитула | `test_form_table_header…` (штамп ≤ 5 столбцов) |
| N6 | build | раздел с нумерацией с числа оригинала, начатый таблицей, — пустой абзац 1 pt перед ней (LibreOffice теряет pgNumType start) | `test_page_numbers_restart_before_leading_table` |
| N7 | pipeline `extract` | PDF без разметки со сканами меньше чем на половине листов — режим текстового слоя | (регрессия) |
| N8 | layout `_regions` | скан в текстовом слое — снимком листа с переведённого PDF; посреди тела — без своего колонтитула, в начале — целиком | `test_scan_page_inside_text_layer…` |
| N9 | struct `layout` | текстовый слой: поля и верх тела — и по таблицам, без снимков; картинка больше ¼ листа и картинки листа-скана — не логотип колонтитула | там же |

| N14 | build `_fit_words` | ячейки в один столбец из строк с объединениями — в счёт; слово не влезает и расширить нечем — кегль ячейки производным стилем, до 60 % | `test_narrow_columns_without_room_shrink_by_style` |
| N15 | layout `group` | столбик коротких (≤ 3 слов) значений против подписей слева — по строке | `test_short_values_against_labels…` |

Затронутые пороги (к сведению в константы): «скан» листа — картинки ≥ 50 % площади (`is_scan`, `scanned`);
отметка бланка 6–20 pt; «короткая строка» значения — ≤ 3 слов; кегль узкого столбца — не меньше 60 %.

Открыто после ночи: рамки полей ввода бланка (коды в рамках, пустые окошки значений) не переносятся; очень узкие
столбцы (22–37 pt) — слово рвётся и при 60 % кегля, нужен мягкий перенос по слогам; кружки отметок — кеглем тела,
мельче оригинала.
